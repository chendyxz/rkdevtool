## RKDevTool v0.18.0

**Release date:** 2026-09-24
**Full changelog:** https://github.com/chendyxz/rkdevtool/compare/v0.17.0...v0.18.0

### Highlights
- **Windows builds:** the project now ships an NSIS installer for Windows x86_64 alongside the Apple Silicon `.dmg`. Windows packages bundle ADB, so APK install and the device log viewer work without a separate platform-tools install.
- **Platform-aware packaging:** every bundled toolchain is resolved per target, and each platform bundles (and configures) only what it actually ships.

### Added
- **Windows CI job** (`windows-latest`): builds `x86_64-pc-windows-msvc`, uploads an artifact on `main`, and publishes the NSIS installer to the same Release on `v*` tags. Both jobs share a `concurrency` group so their `latest.json` platform entries cannot overwrite each other.
- **`packaging/windows/fetch-platform-tools.sh`** fetches Google's official `platform-tools-latest-windows.zip` and installs `adb.exe` plus the `AdbWinApi` / `AdbWinUsbApi` DLLs into the resource directory. The binaries are not committed; CI runs the script before building.
- **`src-tauri/src/platform.rs`** centralizes per-target facts: ADB resource directory and file name, `hide_console` / `adb_command` helpers, and the new `get_platform` command the frontend uses at startup.
- **`usePlatform` composable** so the UI can hide entries whose toolchain is not bundled for the running platform.
- **Per-platform Tauri configuration** (`tauri.macos.conf.json`, `tauri.windows.conf.json`, `tauri.linux.conf.json`) replacing the single cross-platform `bundle` block. Windows uses an NSIS `currentUser` installer with Simplified Chinese and English, and Windows auto-update keeps the `passive` install mode.

### Improved
- **ADB resolution** is no longer hard-coded to `resources/platform-tools/macos-arm64`: `adb.rs` and `logcat.rs` share one lookup that picks the right directory and executable name per target, and the error message now names the missing path.
- **No console window flashes on Windows:** all child processes (`upgrade_tool`, `adb`) go through one helper that sets `CREATE_NO_WINDOW`, replacing the previous single call site.
- **README** documents the platform feature matrix, the bundled ADB sources per platform, and the Windows release steps; release links point at the current repository.

### Compatibility
- **Replace firmware APK** requires the e2fsprogs toolchain (`debugfs`, `e2fsck`) which is only bundled with the macOS build. The page is hidden on Windows and the backend command returns an explicit error instead of failing on missing binaries.
- Linux still builds from source with the existing `AppImage` / `.deb` targets; no Linux ADB or e2fsprogs build is bundled yet.

### Validation
- Automated test suite: 77 library tests passing.
- `cargo check --all-targets` completes without warnings for the macOS target, and the non-macOS `tool_dir` branch was type-checked by temporarily inverting the `cfg` gates.
- Frontend: `vue-tsc --noEmit` and `vite build` complete without errors.
- The Tauri platform configs were merged with RFC 7386 semantics (matching `tauri-utils`) and every referenced `bundle.resources` path was confirmed to exist per platform.
