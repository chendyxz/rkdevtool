## RKDevTool v0.19.0

**Release date:** 2026-09-28
**Full changelog:** https://github.com/chendyxz/rkdevtool/compare/v0.18.1...v0.19.0

### Highlights
- **Device screenshots, like Android Studio.** The Device Log page can grab the current screen with one click, preview it in the app, retake it, and save it as a PNG. Nothing is written to the device: the PNG comes back over `adb exec-out screencap -p` and goes straight to the preview.
- **Readable update dialog.** Release notes are Markdown and can be dozens of lines long, which the native dialog used to dump verbatim. The dialog now shows a short plain-text digest — the `### Highlights` bullets when present — plus a link to the full notes on GitHub.
- **More room for logs.** On the Device Log page the right-hand log panel no longer competes with the log view itself: the page gets the full width and the panel returns as soon as you switch to another page.

### Added
- **Screenshot (Device Log page):** captures the current device frame, shows resolution and capture time, and offers **Retake** and **Save**. The PNG is fetched as raw bytes over IPC and previewed through a blob URL — no base64, no `assetProtocol`, and no temporary file on the device. Saving reuses the frame already held by the backend, so the bytes never travel back through JavaScript. Closing the dialog drops the preview from memory.
- **Refresh (Device Log page):** re-establishes the log stream from the device (buffered lines and the pause state are reset, auto-scroll returns to the bottom) instead of asking you to stop and start. The old `adb logcat` process is always killed first, so a refresh never leaves two streams running.
- **Link to the full release notes** in the update dialog whenever the digest omits anything, pointing at `releases/tag/v<version>`.

### Improved
- **`invoke` payloads stay small.** `capture_screenshot` replies with a Tauri raw-bytes response and caches the PNG in `AppState.last_screenshot`; `save_screenshot` then only receives a path. Returning the image to JavaScript and back would have degraded it into a JSON array of numbers — several MB of PNG become tens of MB of text.
- **Screenshot errors are checked twice:** the `adb` exit status, and the PNG signature of the output. A device that is offline or unauthorized returns `error: device 'X' not found` on stderr with an empty stdout, and the dialog reports it instead of rendering a broken image.
- **Device Log toolbar** keeps Start/Stop as the only state-dependent buttons; Refresh, Screenshot and the rest stay in a stable position, and Screenshot is disabled while no ADB device is connected.
- **Escape key ownership:** the screenshot dialog claims `Escape` (closing itself) before the page's handler runs, so dismissing it from fullscreen no longer exits fullscreen as a side effect.

### Validation
- Automated test suite: 81 library tests passing (up from 80). New coverage: `accepts_only_png_screenshot_bytes` (PNG signature accepted; empty output and `error: device offline` text rejected).
- `cargo check` and `npm run build` (including `vue-tsc --noEmit`) complete without warnings.
- `adb exec-out screencap -p` failure behaviour was verified against the bundled platform-tools: exit code 255, empty stdout, and the device error on stderr.
- macOS and Windows installers are built and published by the same workflow as v0.18.1.
