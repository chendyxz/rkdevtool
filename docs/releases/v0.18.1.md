## RKDevTool v0.18.1

**Release date:** 2026-09-24
**Full changelog:** https://github.com/chendyxz/rkdevtool/compare/v0.18.0...v0.18.1

### Highlights
- **Burn Parameters works on Android 10+ devices.** Writing an authorization code to a device whose `/system` is protected by `dm-verity` no longer fails at the `remount` step: the app now disables verity, performs the one extra restart that change requires, and continues.
- **No more `$ANDROID_PRODUCT_OUT` error.** The step that flushed the write cache used the host-side AOSP command `adb sync`, which aborted with `adb: product directory not specified; set $ANDROID_PRODUCT_OUT`. It now flushes the *device* write cache with `adb shell sync`.

### Fixed
- **Burn Parameters aborted at the flush step** with `adb: product directory not specified; set $ANDROID_PRODUCT_OUT`, and because a failed step also skipped the trailing `reboot`, the device never restarted even though the values had already been written.
- **`/system` remount on dynamic-partition devices:** `adb disable-verity` is issued before `remount` (best effort, so user builds and devices without AVB simply skip it), and when its output asks for a restart the app reboots once, waits for `adbd` to come back, and re-establishes root before continuing.
- **Failures now say what failed.** A step error reports the exact command, the device message, and the output of every previous step, instead of a bare line such as `error: closed`.
- **Transient `adb` transport errors** (`device offline`, `device not found`, `closed`, `connection reset`) are retried for up to 30 s, which covers the window where `adbd` has not finished restarting after `root` or `reboot`.

### Improved
- **Release body is generated by CI:** both platform jobs read `docs/releases/v<version>.md` and pass it to `tauri-action` as a multi-line output. The same text lands in the GitHub Release and in `latest.json`, so the in-app update dialog shows the real notes instead of the placeholder sentence. A missing file only produces a warning and falls back to the previous text.
- **Burn Parameters log panel** now shows the progress line when the extra verity restart is needed, so the pause is visible instead of looking like a hang.

### Validation
- Automated test suite: 80 library tests passing (up from 77). New coverage: `disable-verity` output classification (`detects_when_disable_verity_requires_a_restart`), retry classification (`only_retries_transport_errors`), and failure message composition (`failure_message_keeps_the_failed_command_and_previous_output`).
- `cargo check --lib` completes without warnings.
- macOS and Windows installers are built and published by the same workflow as v0.18.0.
